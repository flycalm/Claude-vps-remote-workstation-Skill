# VPS 远程桌面工作站

根据目标服务器的现状部署或排查工作站。以 Ubuntu 24.04、2C4G、无物理显卡的实践为参考，按实际发行版、网络接口、管理端口和用户调整配置。

## 执行流程

1. 明确任务是新建部署、修改现有配置还是排障。先检查发行版、内存、桌面用户、实际 SSH 端口、网卡、默认路由、已有代理和服务状态；仅询问无法从环境获取且会影响实施的信息。
2. 读取对应章节，先区分模板占位值与实际配置。替换订阅地址、代理主机、端口和凭据；确认使用的程序已安装及其路径。不要把示例密码用作真实密码，也不要将真实凭据写入可发布的文档或仓库。
3. 修改前备份受影响文件并记录原有服务、路由和 DNS 状态。沿用已经可用的配置，只实施用户任务需要的变更；系统时区、语言、IPv6 和 Swap 等调整按实际需要决定。
4. 涉及 TUN 或路由时先执行下方连接保护流程。其他配置按参考章节实施，并在重启对应服务前检查配置。
5. 分别验证管理连接、桌面会话、代理出口和目标应用。排障时一次调整一个因素并观察结果，避免用反复登录代替网络诊断。
6. 汇报已完成的变更、验证结果、仍未验证的项目，以及本次变更对应的恢复方式。没有实际执行的检查不得报告为通过。

## TUN 与管理连接保护

- 在启动 TUN 前，确认云厂商控制台或其他独立救援通道可用；备份当前配置并保留现有管理会话。
- 使用实际 SSH/RDP 监听端口和网络接口设置保护规则。先检查现有策略路由，避免覆盖其他服务占用的优先级；参考文档中的 `22`、`3389`、`eth0` 和优先级只是该示例的取值。
- 在开启 TUN 前后检查到当前客户端的管理流量回程路由，并通过第二个连接确认仍能登录。若无法确认回程和恢复路径，停在配置准备阶段，不启动会改变路由的服务。
- 修改 Mihomo 配置后先运行 `mihomo -t -d /etc/mihomo`，根据实际安装路径调整命令。校验失败时先修正配置，不重启服务。
- 回滚以备份和记录的原状态为准，只撤销本次创建或修改的规则与服务配置。参考文档 §8 是恢复直连的示例，不能代替恢复现场原有状态。

## 浏览器与登录排障

- 先核验实际出口、DNS、代理链路和浏览器配置，再判断登录问题；区分观察到的现象和对原因的推测。
- 保持浏览器原生平台信息，按需使用独立 Profile；确认没有运行中的实例占用 Profile 后，才处理异常退出残留的锁文件。
- 如采用参考文档的 Firefox 配置，核验专属代理端口是否可用，并由用户在同一浏览器会话内完成邮箱及登录验证。
- 仅在用户要求执行部署或修改时操作目标服务器。若任务是整理或解释文档，交付文档即可。
